# Для мейнтейнера

Раздел для того, кто развивает сам шаблон. Разработчику проекта, созданного через `create-nest-nuxt`, он не нужен: генератор будет удалять его при создании проекта.

## Ветки шаблона

Варианты шаблона живут в отдельных ветках, и каждая следующая надстраивается над предыдущей:

```
main → auth-session → postgres-prisma
```

Изменения вносятся в самую нижнюю ветку, которой они касаются, и вливаются вверх по цепочке merge-коммитами. Это делает workflow `branch-sync`: когда CI ветки прошёл, он вливает её в следующую.

### `.env` при переключении веток

Локальный `.env` при переключении веток не обновляется: в нём может не оказаться переменных, которые появились в новой ветке. Сверьте его с `.env.example` и добавьте недостающие. Например, при переходе с `main` на `postgres-prisma` в `apps/backend/.env` может не быть переменных `POSTGRES_*` — скопируйте их из `apps/backend/.env.example`.

## Тесты скриптов

Скрипты из `scripts/` покрыты тестами в `scripts/tests/`. Тесты проверяют сам шаблон, поэтому в `package.json` для них нет команды, а генератор удаляет папку при создании проекта.

Тесты запускает CI. Чтобы запустить их локально:

```sh
node --test "scripts/tests/*.test.mjs"
```

Каждый тест работает с копией `scripts/` во временной папке (`scripts/tests/sandbox.mjs`), поэтому ваши `.env` и запущенный `pnpm dev` не затрагиваются.
