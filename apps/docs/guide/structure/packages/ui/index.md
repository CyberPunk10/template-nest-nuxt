# packages/ui

Библиотека Vue-компонентов. Используется только фронтендом.

```
packages/ui/
├── src/
│   ├── components/     UiButton, UiBadge, UiCard
│   └── index.ts
├── package.json
└── tsconfig.json       наследует base, добавляет DOM
```

## Куда класть компонент

Принцип простой: в общий пакет попадают переиспользуемые компоненты, которые ничего не знают о приложении — ни о сторе, ни об API, ни о страницах.

- **В общий пакет** (`packages/ui/src/components/`) — простые компоненты без логики приложения: кнопки, бейджи, карточки, поля. Данные получают через props, о действиях сообщают событиями.
- **Во frontend** (`apps/frontend/app/components/`) — всё, что ходит в API, работает со стором или знает о страницах.
- **Не уверены** — кладите во frontend: перенести в пакет потом несложно.

## Зачем отдельный пакет

Чтобы те же компоненты подключил второй фронтенд — чаще всего это админка. Если второго фронтенда не будет, пакет можно убрать и держать компоненты во frontend.

## Почему без сборки

Пакет остаётся исходниками. Его потребляет только frontend, а Vite обрабатывает `.vue` и `.ts` напрямую — промежуточная сборка не нужна.

Скомпилировать его обычным `tsc` и не получилось бы: `.vue`-файлы требуют `vue-tsc` и отдельного пайплайна. `tsconfig.json` здесь нужен лишь для `vue-tsc --noEmit` при проверке типов.

Поэтому `main` указывает прямо на `src/index.ts` — так же, как у [shared](../shared/). Отличается только проверка типов: здесь нужен `vue-tsc`, там достаточно `tsc`.

## Своя настройка TypeScript

Наследует `tsconfig.base.json`, но добавляет библиотеку `DOM` — в базовом конфиге её нет намеренно, он общий и для бэкенда.

Манифест пакета — [package.json](./package-json).
