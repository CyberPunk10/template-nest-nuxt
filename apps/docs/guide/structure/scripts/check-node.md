# check-node.mjs

Проверяет версию Node перед `pnpm dev` — его вызывает [`predev.mjs`](./predev) первым шагом.

Нужная версия берётся из `engines.node` корневого `package.json` (сейчас `>=24.22.1`). Если текущий Node старше, подготовка останавливается с подсказкой:

```
[predev.mjs] ✗ node: Node.js 24.13.0, but the project needs >=24.22.1.
  Switch this terminal:        nvm use
  Optional, for new terminals: nvm alias default 24.22.1
```

Подсказка зависит от того, что есть на машине:

| Что есть | Подсказка |
|---|---|
| nvm и нужная версия Node | `nvm use` — переключить терминал |
| nvm, но нужной версии нет | `nvm install` — установить и переключить |
| nvm нет | команда установки nvm (та же, что на странице [«Подготовка»](../../getting-started/setup)), затем `nvm install` в новом терминале |

Последней строкой всегда идёт необязательная `nvm alias default` — чтобы новые терминалы открывались с нужной версией. Версию для неё скрипт берёт из `.nvmrc`, а если его нет — минимальную из `engines.node`. nvm — функция оболочки, поэтому скрипт узнаёт о нём по переменной `NVM_DIR`. Если Node ставится другим менеджером версий (fnm, Volta, asdf), подсказка предложит nvm — используйте свой менеджер.

## Зачем

pnpm и сам проверяет `engines`, но для каждого приложения отдельно: без этой проверки `pnpm dev` падает трижды одной и той же ошибкой `ERR_PNPM_UNSUPPORTED_ENGINE` — от Nest, Nuxt и документации — и не подсказывает, что делать. Здесь ошибка одна, до запуска приложений.

## Что проверяется

Понимается только диапазон вида `>=x.y.z`, как в этом проекте. Если `engines.node` записан иначе (`^24`, `24.x`), скрипт ничего не проверяет и запуск не останавливает — это решит pnpm.
