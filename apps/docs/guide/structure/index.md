# Структура проекта

Монорепо из пяти пакетов: три приложения в `apps/`, две общие библиотеки в `packages/`.

```
template-nest-nuxt/
├── apps/
│   ├── backend/          NestJS API
│   ├── frontend/         Nuxt 4
│   └── docs/             VitePress — эта документация
├── packages/
│   ├── shared/           типы (DTO) и переводы
│   └── ui/               Vue-компоненты
├── infra/
│   └── nginx/            reverse proxy: конфиг и Dockerfile
├── scripts/              Node-скрипты для pnpm-команд
├── .husky/               git-хуки
├── docker-compose.yml
└── конфиги в корне       pnpm, TypeScript, ESLint
```

Как пакеты зависят друг от друга — в [Архитектуре](../architecture).

## Конфиги

| Файл                    | Зачем                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm-workspace.yaml`   | Объявляет, какие папки — воркспейсы (`apps/*`, `packages/*`). Без него pnpm не свяжет пакеты между собой                                     |
| `tsconfig.base.json`    | Общие настройки TypeScript: строгость и проверки. Наследуется конфигами приложений                                                           |
| `eslint.config.base.js` | Правила линтера: сами правила, стиль, глобальные переменные                                                                                  |
| `eslint.config.js`      | Реэкспорт базового — одна строка. Нужен, потому что ESLint ищет в корне файл со стандартным именем, а приложения импортируют `base` напрямую |
| `lint-staged.config.js` | Что запускать на файлах в staged: `eslint --fix` для js/ts/vue                                                                               |
| `.npmrc`                | `engine-strict=true` — `pnpm install` откажется ставить зависимости на неподходящей версии Node, а не сломается позже на рантайме            |
| `.nvmrc`                | Версия Node для `nvm use` — пара к `engines` из корневого `package.json`                                                                     |
| `.dockerignore`         | Что **не** попадёт в build-контекст: `node_modules`, сборки, `.env` (кроме `.example`). Прямо влияет на размер образов и скорость сборки     |
| `pnpm-lock.yaml`        | Один лок-файл на всё монорепо — следствие workspaces. Точные версии всех зависимостей, включая транзитивные                                  |

Разбор TypeScript-конфигов по слоям — [tsconfig.base.json](./tsconfig-base).

## Куда добавлять новое

| Что                             | Куда                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| Страница фронтенда              | `apps/frontend/app/pages/` — роут создастся сам по имени файла                        |
| Модуль API                      | `apps/backend/src/modules/<имя>/` + регистрация в `app.module.ts`                     |
| Тип, нужный обеим сторонам      | `packages/shared/src/` — иначе он окажется продублирован                              |
| Тип, нужный одной стороне       | внутрь самого приложения, не в `shared`                                               |
| Vue-компонент общего назначения | `packages/ui/src/components/`                                                         |
| Компонент только для фронтенда  | `apps/frontend/app/components/` — автоимпорт по имени файла                           |
| Node-скрипт для pnpm-команды    | `scripts/` + строка в корневом `package.json`                                         |
| Страница документации           | `apps/docs/guide/` + такой же файл в `en/` и `th/` + пункт в `.vitepress/config/*.ts` |
