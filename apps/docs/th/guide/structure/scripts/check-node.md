# check-node.mjs

ตรวจสอบเวอร์ชัน Node ก่อน `pnpm dev` — [`predev.mjs`](./predev) เรียกใช้เป็นขั้นตอนแรก

เวอร์ชันที่ต้องการมาจาก `engines.node` ใน `package.json` ที่ root (ตอนนี้คือ `>=24.22.1`) ถ้า Node ที่ใช้อยู่เก่ากว่า การเตรียมจะหยุดพร้อมคำแนะนำ:

```
[predev.mjs] ✗ node: Node.js 24.13.0, but the project needs >=24.22.1.
  Switch this terminal:        nvm use
  Optional, for new terminals: nvm alias default 24.22.1
```

คำแนะนำขึ้นอยู่กับสิ่งที่มีในเครื่อง:

| สิ่งที่มี | คำแนะนำ |
|---|---|
| มี nvm และ Node เวอร์ชันที่ต้องการ | `nvm use` — สลับเวอร์ชันในเทอร์มินัล |
| มี nvm แต่ไม่มีเวอร์ชันที่ต้องการ | `nvm install` — ติดตั้งและสลับ |
| ไม่มี nvm | คำสั่งติดตั้ง nvm (แบบเดียวกับหน้า [การเตรียมความพร้อม](../../getting-started/setup)) แล้วรัน `nvm install` ในเทอร์มินัลใหม่ |

บรรทัดสุดท้ายคือ `nvm alias default` ซึ่งไม่บังคับ เพื่อให้เทอร์มินัลใหม่เปิดด้วยเวอร์ชันที่ต้องการ เวอร์ชันนี้มาจาก `.nvmrc` หรือถ้าไม่มีไฟล์นี้ จะใช้เวอร์ชันขั้นต่ำจาก `engines.node` nvm เป็นฟังก์ชันของเชลล์ สคริปต์จึงตรวจพบจากตัวแปร `NVM_DIR` ถ้าติดตั้ง Node ด้วยตัวจัดการเวอร์ชันอื่น (fnm, Volta, asdf) คำแนะนำจะยังเสนอ nvm — ให้ใช้ตัวจัดการของคุณเอง

## ทำไมต้องมี

pnpm ก็ตรวจ `engines` เองเช่นกัน แต่ตรวจแยกทีละแอป: ถ้าไม่มีการตรวจนี้ `pnpm dev` จะล้มสามครั้งด้วย error เดียวกัน `ERR_PNPM_UNSUPPORTED_ENGINE` จาก Nest, Nuxt และเอกสาร โดยไม่บอกว่าต้องทำอะไร ที่นี่จะมี error เดียวก่อนแอปเริ่มทำงาน

## ตรวจอะไรบ้าง

รองรับเฉพาะช่วงเวอร์ชันแบบ `>=x.y.z` เหมือนในโปรเจกต์นี้ ถ้า `engines.node` เขียนแบบอื่น (`^24`, `24.x`) สคริปต์จะไม่ตรวจและไม่หยุดการเริ่มทำงาน — ให้ pnpm จัดการเอง
